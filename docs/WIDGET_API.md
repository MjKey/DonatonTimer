# Виджет таймера: API и подключение

Руководство описывает текущий локальный API DonatonTimer v3.0.7. Оно подходит
для готового OBS-оверлея, собственного HTML-виджета и внешней панели управления.

Приложение DonatonTimer должно быть запущено: оно хранит состояние таймера,
обрабатывает донаты и отправляет обновления подключённым виджетам.

## Быстрый запуск готового оверлея

1. Запустите DonatonTimer и настройте начальное время и нужные донат-сервисы.
2. В OBS добавьте источник **Браузер**.
3. В поле URL укажите `http://127.0.0.1:7575/timer`.
4. Укажите нужную ширину и высоту источника.
5. Оформление готового оверлея настраивается в редакторе стилей приложения.

Настройка **Внешний вид → Стиль интерфейса приложения** меняет только
настольный интерфейс. Она не меняет CSS вашего HTML-виджета.

## Адреса и порты

| Адрес по умолчанию | Назначение |
| --- | --- |
| `http://127.0.0.1:7575/timer` | Готовая страница таймера для OBS |
| `http://127.0.0.1:7575/dashboard` | Страница управления и статистики |
| `http://127.0.0.1:7575/mini` | Компактная панель, например для дока OBS |
| `http://127.0.0.1:7575/` | Перенаправление на `/dashboard` |
| `ws://127.0.0.1:3434/` | Данные и команды через WebSocket |

HTTP-маршруты возвращают HTML. REST-методы вроде `GET /api/timer` и
`POST /api/timer/start` не реализованы. Данные и команды передаются через
WebSocket на отдельном порту с путём `/`; путь `/ws` не используется.

Порты задаются в **Настройки → Таймер → Настройки портов**. Если стандартный
порт занят, при запуске приложение пробует HTTP `7576` и WebSocket `3435`.
Фактический порт можно проверить в журнале приложения. Указывайте его в виджете.

`127.0.0.1` подходит, если OBS и DonatonTimer работают на одном компьютере.
Для другого устройства укажите локальный IP компьютера с DonatonTimer,
например `ws://192.168.1.10:3434/`. Этот порт должен быть доступен между
устройствами в локальной сети.

## Подключение собственного HTML-виджета

Готовый пример находится в
[`examples/custom-widget/widget.html`](../examples/custom-widget/widget.html).
Он использует прозрачный фон, показывает `ЧЧ:ММ:СС`, отмечает потерю связи и
переподключается через 1,5 секунды. Внешние библиотеки и сервер для HTML не нужны.

1. Скопируйте HTML в постоянную папку для виджетов.
2. При необходимости измените `WS_URL` в начале JavaScript: IP и порт должны
   соответствовать запущенному приложению.
3. В OBS добавьте источник **Браузер**, включите **Локальный файл** и выберите HTML.
4. Установите размер, например **600 × 160**.
5. Запустите DonatonTimer. Виджет автоматически получит данные.

Для изменения шрифта, цвета, фона и размера отредактируйте CSS внутри HTML.
Для виджета, который только отображает время, отправлять команды не требуется.
Ключ или URL виджета DonationAlerts передавать в HTML не нужно: подключение
к донат-сервису настраивается в настольном приложении.

## Формат сообщений

Все сообщения — текстовые WebSocket-кадры с JSON-объектом. Поле `action`
задаёт тип сообщения. После подключения клиент получает два отдельных
сообщения: `update_timer` и `update_donations` с кэшированным состоянием.

### Остаток времени: сервер → клиент

```json
{
  "action": "update_timer",
  "duration": 3661
}
```

`duration` — целое число оставшихся секунд. `3661` отображается как `01:01:01`.
Количество часов может превышать 23; это длительность, а не время суток.

Обновления отправляются при изменении состояния таймера. Во время отсчёта
это происходит примерно раз в секунду. Добавление времени, вычитание, сброс,
запуск и остановка также вызывают обновление.

Виджет должен показывать полученное значение. Собственный отсчёт через
`setInterval` может расходиться с приложением при паузе, задержках или донатах.

Минимальный обработчик:

```html
<div id="timer">--:--:--</div>
<script>
  const socket = new WebSocket('ws://127.0.0.1:3434/');

  socket.onmessage = ({ data }) => {
    let message;
    try { message = JSON.parse(data); }
    catch { return; }

    if (message?.action !== 'update_timer') return;
    const total = message.duration;
    if (!Number.isSafeInteger(total) || total < 0) return;

    const hours = Math.floor(total / 3600);
    const minutes = Math.floor(total / 60) % 60;
    const seconds = total % 60;
    document.getElementById('timer').textContent =
      [hours, minutes, seconds]
        .map(value => String(value).padStart(2, '0'))
        .join(':');
  };
</script>
```

В полном примере из `examples/` дополнительно реализовано переподключение.

### Статистика донатов: сервер → клиент

```json
{
  "action": "update_donations",
  "recentDonations": [
    { "username": "Viewer", "minutesAdded": 15 }
  ],
  "topDonators": {
    "Viewer": 45,
    "AnotherViewer": 20
  }
}
```

| Поле | Содержимое |
| --- | --- |
| `recentDonations` | Последние донаты, от новых к старым |
| `recentDonations[].username` | Имя пользователя |
| `recentDonations[].minutesAdded` | Изменение времени от доната в минутах, округлённое до целого |
| `topDonators` | Имя пользователя → суммарное изменение времени в минутах |

В режиме вычитания значения минут могут быть отрицательными. `topDonators`
передаётся объектом без готовой сортировки. Например, для топа по убыванию:

```js
const top = Object.entries(message.topDonators)
  .sort((a, b) => b[1] - a[1]);
```

Сообщение содержит актуальные списки целиком: заменяйте ими отображаемую
статистику. Оно не является отдельным уведомлением о новом донате, поэтому
не запускайте донат-анимацию на каждое `update_donations`, включая подключение.
Для отображения имён используйте `textContent`.

## Команды управления: клиент → сервер

Команды отправляются по тому же соединению, когда `socket.readyState`
равен `WebSocket.OPEN`.

| JSON-команда | Действие |
| --- | --- |
| `{"action":"start"}` | Запустить отсчёт, если остаток больше нуля |
| `{"action":"stop"}` | Приостановить отсчёт, сохранив остаток |
| `{"action":"change_time","seconds":300}` | Добавить 5 минут |
| `{"action":"change_time","seconds":-60}` | Вычесть 1 минуту |

Пример отправки:

```js
if (socket.readyState === WebSocket.OPEN) {
  socket.send(JSON.stringify({ action: 'change_time', seconds: 300 }));
}
```

`seconds` должен быть целым JSON-числом. Это изменение относительно текущего
остатка, а не установка абсолютного значения. При вычитании остаток
ограничивается нулём. Отдельных команд установки времени и сброса нет.

## Ограничения текущей реализации

- В сообщениях нет поля `isRunning`. По одному `duration` нельзя достоверно
  определить, запущен таймер или находится на паузе.
- Команды не имеют идентификаторов запросов, подтверждений и JSON-ответов
  об ошибках. Изменённое время приходит обычным `update_timer`.
- Снимок при подключении берётся из кэша WebSocket-сервера. После запуска
  приложения он может содержать `0` и пустую статистику до первого уведомления
  об изменении соответствующего состояния.
- При потере соединения последнее значение устаревает. Показывайте статус
  отключения и переподключайтесь; пример HTML делает это автоматически.
- Авторизация, токены доступа и TLS/WSS в локальном сервере не реализованы.
  Подключившийся клиент может как получать данные, так и отправлять команды.
  Локальный сервер не следует публиковать напрямую в Интернет.

## Если виджет не работает

| Симптом | Что проверить |
| --- | --- |
| `--:--:--` или «Нет связи» | Приложение запущено; адрес, фактический WS-порт и доступность сети верны |
| Подключение к `/timer` не даёт JSON | `/timer` — HTML-страница; данные передаются на отдельном WebSocket-порту |
| Первый остаток равен нулю | Возможно, ещё не обновился кэш сервера; следующее изменение таймера пришлёт его значение |
| Данные перестали обновляться | Соединение закрыто или приложение остановлено; используйте переподключение |
| С другого компьютера соединения нет | Нужен IP компьютера с DonatonTimer вместо `127.0.0.1` и доступ к порту в локальной сети |
| Изменение времени игнорируется | Соединение открыто, `action` равен `change_time`, а `seconds` — целое число |
